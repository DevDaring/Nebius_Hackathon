# NemoTwins API — agent, capabilities and admin

Core endpoints are in [`API_CONTRACT.md`](API_CONTRACT.md). Clients must tolerate absent optional fields.

## Languages

`lang` accepts `en-US`, `es-ES`, `fr-FR`, `de-DE`, `it-IT`, `ja-JP` (the languages listed on the NVIDIA
Nemotron 3 Nano model card). Any other code is answered in `en-US`.

## `GET /api/capabilities` (no auth, no secrets)

```json
{
  "app_name": "NemoTwins",
  "schema_version": "1.0",
  "locales": ["en-US", "es-ES", "fr-FR", "de-DE", "it-IT", "ja-JP"],
  "default_locale": "en-US",
  "mode": "live | demo",
  "inference": {"provider": "nebius_tokenfactory", "chat_model": "nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B" , "available": true},
  "features": {
    "vision":     {"enabled": true,  "model": "google/gemma-3-27b-it", "nvidia": false, "provider": "nebius_tokenfactory", "reason": null},
    "speech":     {"enabled": false, "reason": "No speech (ASR/TTS) model is available on Nebius Token Factory."},
    "guardrails": {"enabled": true,  "engine": "nemoguardrails", "model": "nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B"},
    "fish":       {"enabled": true}
  }
}
```

`features.*.reason` is a short English explanation shown when a feature is off.

## Agent reply (`POST /api/agent/chat`, `/api/agent/confirm`)

```json
{
  "execution_id": "hex",
  "schema_version": "1.0",
  "clarification": null,
  "disclosures": [],
  "checks": {"numbers": "passed | failed | not_run", "guardrails_input": "passed | blocked | not_run | unavailable",
             "guardrails_output": "passed | blocked | not_run | unavailable"},
  "model": {"provider": "nebius_tokenfactory", "model_id": "nvidia/... | null", "live": true}
}
```

* `clarification` (object or null). When the assistant needs one detail before it can simulate:
  `{"slot": "portion | time | unit | food", "question": "<localised question>",
    "options": [{"label": "<localised>", "text": "<text to send back as the next user message>"}],
    "skip": {"label": "<localised>", "text": "<original message>", "skip_slots": ["portion"]}}`.
  The UI shows the question with the options as quick-reply buttons; choosing an option sends its
  `text` as a new chat message (the original message rewritten with the chosen detail, in the user's
  language). Choosing `skip` re-sends `skip.text` with `"skip_slots": skip.skip_slots` in the chat
  request body; the assistant then continues with an explicitly wider range (portion uncertainty
  widened, `disclosures` contains `wider_range`) or says it cannot proceed reliably.

`POST /api/agent/chat` body gains optional `"skip_slots": ["portion" | "time" | "unit" | "food"]`.
* `disclosures`: `[{"kind": "stale_data | exploratory | ranking_uncertain | fallback | not_validated | wider_range", "text": "<localised>"}]` —
  render as small labelled notes under the reply, never hidden.
* `checks.numbers === "passed"` is the only condition under which the UI may say "All numbers checked".
* `source`: (`live` = generated by the language model this turn; `fixture` =
  deterministic template / offline). `source_detail` names the exact model id or "template".

## Further reading

Agent replies gain `references` (object or null) for education and evidence questions:
`{"topic": "time_in_range", "chosen_by": "nemotron:<model> | keywords", "provider": "tavily",
"items": [{"title", "url", "domain", "snippet"}], "allowlist": [...], "query": "<fixed topic query>"}`.
Display-only: render as links (new tab, `rel="noopener noreferrer nofollow"`) with the snippet as a quotation
and the note that it is general information, not about the user's twin. `GET /api/capabilities` gains
`features.references {enabled, provider, kind, reason}`.

## Meal photo

`POST /api/meal/photo`: when vision is off it returns 503 with
`{"detail": {"code": "vision_unavailable", "message": "..."}}`. A successful parse adds
`"recognition": {"model": "...", "nvidia": false, "provider": "nebius_tokenfactory"}`.

## Speech

`/api/speech/stt` and `/api/speech/tts` return **501** `{"detail": {"code": "speech_unavailable", ...}}`
(no Token Factory speech model). `audio_url` in agent replies is always `null`.
